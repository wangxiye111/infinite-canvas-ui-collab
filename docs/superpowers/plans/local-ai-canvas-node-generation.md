# 普通图片／视频节点平台生成实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 直接执行，用户已授权继续开发。

**Goal:** 在普通图片／视频节点内完成平台预设选择、参考输入、手动提交、结果回填、历史回看和恢复，提供可执行的用户测试步骤。

**Architecture:** 复用 canvas-connectors 的任务、文件和预设服务，通过现有 CanvasPluginHost 更新普通节点。节点保存预设、输入和任务快照；结果保存浏览器素材库，服务端已有本地结果文件。既有 GPT／Gemini／API 入口保留。

**Tech Stack:** React、Ant Design、TypeScript、Zustand、localforage、现有 Node.js 连接服务。

**Spec:** `docs/superpowers/specs/local-ai-canvas-prd.md`，F03–F07 的平台节点流程。

## 约束与审查重点

- 沿用现有开发分支及用户改动，不提交、不合并；不构建、不做语法／类型检查。
- 不新增并发、重试次数、大小或超时限制；复用平台任务节点已有查询间隔。
- 只查询、恢复已有任务；重新生成必须手动开始新一轮，未知任务状态须明确确认。
- 切换画布、删除节点或更换请求时，迟到结果不能写入别的节点；重复导入不能增加重复候选。
- 保留原素材、旧批次、预设和参考快照；选择历史结果不能触发生成。
- 只展示适合当前节点输出类型的可灵、即梦、RunningHub 预设；不猜测平台参数，不默默忽略参考素材。
- 特殊 RunningHub 多类型输出继续使用原任务节点。即梦首尾帧仍待 CLI 帮助验证。
