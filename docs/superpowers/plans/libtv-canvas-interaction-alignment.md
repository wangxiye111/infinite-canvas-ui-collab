# LibTV 主创作交互对齐

**目标：** 纠正平台表单挤占创作入口的问题，按已经选定的 LibTV 参考与已确认 PRD，统一图片／视频编辑器。

**证据：** 已查看 `libtv-research/04-image-node.png`、`05-image-settings.png`、`06-video-node.png`。参考界面是素材引用在上、提示词居中、模型与参数和生成按钮在底部。当前实现多一套平台表单、返回入口及常驻任务文案，破坏同一节点的操作连续性。

**设计：**

- 图片／视频只保留一张编辑器。底部同一个模型菜单选择 GPT／Gemini／已配置 API 模型，以及可灵、即梦和 RunningHub 工作流；未配置平台提供真实配置入口，不伪造可用模型。
- 参考素材仍在顶部，空态显示轻量「画布参考」按钮；有素材时显示缩略图。平台的首尾帧／工作流角色按需编辑。
- 主要区域只写提示词。模型与参数在底栏；连接、计费、任务编号放入菜单或详情，不常驻。
- 已完成后再点生成创建新批次；不确定任务仍先恢复，明确核查后才允许新批次。历史与候选通过轻量入口展开。
- 画布顶部收起辅助菜单；主创作界面只保留项目、必要设置及创作助手。沿用当前主题 token，浅深色一致。
- 本轮不重做后端、不安装 CLI、不发起真实生成；保留所有已有任务和结果。

**实施：**

- [x] 抽取现有平台节点控制逻辑为同目录 hook，保存／恢复规则不变；为统一模型切换及连续生成增加行为测试。
- [x] 统一模型选择、引用区、提示词与底栏；移除平台专用表单和返回入口。
- [x] 精简画布辅助菜单，并在本地浏览器对照参考截图检查图片、视频及模型菜单。
- [x] 更新待测试、TODO、CHANGELOG，明确尚未达到逐像素复刻和真实生成验收的范围。

**执行约束：** 当前用户已指定 LibTV 且要求修正已交付设计，不重复要求选择视觉方向；直接修正已授权范围。保留用户工作区，不构建／类型检查、不改超时或并发值。

**验收记录：** 17 项相关行为测试通过；IAB 独立页面导入合成样例，验证未知任务切换阻止、核查后新一轮、平台切到 API 提示词保留、API 下历史选图可用。独立审查发现的历史禁用与失败无提示两项已修复。截图保存在 `libtv-research/15-unified-editor.png`。无构建／类型检查／真实生成。像素细节和真账号接入继续待验收。
